# 生命週期與所有權

前面章節已經使用 `Spawn()` 建立物件、透過 `Destroy()` 吃掉豆子，也曾把 Engine 管理中的玩家與迷宮指標借給其他物件查詢；這些操作看似分散，背後其實都依賴同一份生命週期契約。Engine 必須先確定誰負責釋放物件，再決定一幀進行到一半時能在什麼時候安全地加入或移除物件，否則遊戲程式即使偶爾能執行，也可能留下重複釋放或失效指標等難以追查的錯誤。

```text
以 new 建立物件
       ↓
Spawn() 接管所有權
       ↓
OnSpawn() 執行一次
       ↓
更新、碰撞與繪製
       ↓
Destroy() 或 ClearObjects()
       ↓
Engine 釋放物件
```

本章因此先從所有權開始，釐清原始指標在 `Spawn()` 前後分別由誰負責，接著建立每幀更新、碰撞與繪製的完整順序，最後才說明執行期間的新增與刪除為何必須延後套用。這個順序讓「不要自行 `delete`」不只是孤立規定，也讓「新物件下一幀才更新」能從 Engine 正在保護的流程自然推導出來。

這裡也是整份文件唯一完整列出精確時序的地方；前面章節只在需要時連到本章，而不各自重述一套簡化版本，因此當碰撞中刪除物件、更新中生成敵人，或跨關卡保存借用指標時，都應以本章契約為準。

## 完成本章後

- 能說明 `Spawn()` 前後的所有權由誰負責，以及哪些指標只是借用。
- 能依序列出一幀中的更新、碰撞、延後刪除與繪製。
- 能預測在更新期間建立或銷毀物件時，變更會在哪一個時點生效。
