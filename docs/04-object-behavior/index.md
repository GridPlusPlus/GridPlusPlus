# 讓物件開始行動

前一章已經完成第一個會接受輸入、更新分數並移動地鼠的遊戲，不過當時的重點是看見完整成果，因此只知道要把 `UpdateMole` 交給 `Spawn()`，還沒有進一步說明 Engine 為什麼能在正確時間執行它。本章會把這項機制拆成 `UpdateFn` 與 `CollideFn` 兩個容易辨認的角色，先處理每幀更新，再加入同格碰撞，讓讀者能用普通函式為物件補上行為。

只有一隻地鼠時，`UpdateMole` 可以暫時透過全域變數保存下一次移動時間，問題還不明顯；如果場上同時有三隻移動速度不同的地鼠，它們共用同一個 `next_move`，其中一隻更新時間後，另外兩隻便會跟著等待。`UpdateFn` 仍然能描述移動規則，卻沒有地方保存每隻地鼠各自擁有的資料，因此第 5 章會從這個限制引入繼承，把物件的狀態與行為放回同一個類別中。

## 完成本章後

- 能說明 `UpdateFn` 何時收到目前物件，以及如何透過 `engine()` 查詢世界。
- 能分辨碰撞中的 `self` 與 `other`，並利用 tag 判斷對方身分。
- 能看出共用函式何時因缺少個別資料而不再足夠，為下一章的繼承建立問題意識。
