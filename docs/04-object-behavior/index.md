# 讓物件開始行動

前一章已經完成第一個會接受輸入、更新分數並移動地鼠的遊戲，不過當時的重點是看見完整成果，因此只知道要把 `UpdateMole` 交給 `Spawn()`，還沒有進一步說明 Engine 為什麼能在正確時間執行它。本章會把這項機制拆成 `UpdateFn` 與 `CollideFn` 兩個容易辨認的角色，先處理每幀更新，再加入同格碰撞，讓讀者能用普通函式為物件補上行為。

這種寫法足以完成牆面、豆子與單一玩家，卻會在多個物件需要各自保存計時器、方向或生命值時露出限制，因此本章不會把函式式介面當成所有問題的終點，而會在結尾刻意建立一個它無法自然解決的案例；第 5 章接著從這個問題引入繼承，將每個物件自己的資料與行為重新放在一起。至於繪製雖然也屬於物件行為，多數物件目前仍可沿用預設效果，素材、基本圖形與自訂畫面會集中在第 6 章處理。
