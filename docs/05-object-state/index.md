# 讓每個物件保存自己的狀態

打地鼠只有一隻地鼠，因此一個全域 `next_move` 就能記錄下次移動時間。若產生三隻地鼠，三個物件會呼叫同一個 `UpdateMole`，也會讀寫同一個 `next_move`。第一隻地鼠更新時間後，另外兩隻會看到相同數值，三隻地鼠無法擁有獨立的移動週期。

```cpp
double next_move = 0.0;

void UpdateMole(GridObject* self) {
    if (GetTime() < next_move) return;
    // 三隻地鼠都修改同一個 next_move。
    next_move = GetTime() + 1.0;
}
```

這個問題來自資料的歸屬。分數和遊戲結束時間屬於整局遊戲，可以共用；下一次移動時間屬於單一地鼠，每個 instance 都需要一份。用陣列和物件指標建立對照表雖然可行，卻會讓狀態遠離使用它的行為，新增或刪除物件時也必須同步維護。

C++ class 可以把狀態與使用它的行為放回同一個物件中，而繼承 `GridObject` 之後，新物件仍能沿用座標、素材、tag、碰撞與繪製等既有能力。下一節會沿用上一章留下的地鼠問題，把 `UpdateMole` 與全域 `next_move` 重構成 `Mole` 類別，讓每次建立地鼠都同時建立一份獨立計時器；讀者先看見這項改寫解決了什麼，再認識 `OnSpawn()`、`OnUpdate()`、`OnCollide()` 與 `Render()` 如何讓 Engine 在生命週期的不同階段呼叫自訂物件。

完成這個重構之後，我們才會回頭替第 4 章的函式式介面補上 callback 這個名稱，並比較它和繼承各自適合的問題；這樣一來，繼承不是為了展示 C++ 語法而突然出現，而是因為一個普通函式已經不足以表示每個物件各自擁有的資料。
